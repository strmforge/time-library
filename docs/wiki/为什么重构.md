# 为什么重构

2026.11.23 不是在旧版上加功能，而是把时间图书馆从头重做了一遍。没变的是目标：所有 agent
共用一份记忆，每条记忆都以原话为凭。其余几乎全是新的。

## 改了什么

| | 2026.9.11 及更早 | 2026.11.23 起 |
|---|---|---|
| 跑在哪 | 每台电脑各跑一整套本机服务 | NAS 上一个服务端（Docker），每台电脑一个轻客户端 |
| 谁共用记忆 | 同一台电脑上的 agent | 所有电脑上的所有 agent |
| 存什么 | 整份原始会话，连工具输出等运行态一起 | 只存对话；运行态在本机就丢掉，密钥出电脑前打码 |
| 新 agent 怎么接 | 按产品写适配 | agent 自己描述会话格式、自己检查、自己报上来 |
| 记忆 | 原始记录加两层整理 | 决定、偏好、纠正、事实、教训，每条引用所依据的原话（逐字核对）；分得清用户原话、助手转述、用户贴进来的别人的话；每个项目归纳成经验卡 |
| 模型 | chat/completions | 按任务选模型、可加备用；原生 Responses、Messages；自带本机模型 |
| 安装 | 安装脚本、安装器 | 服务端 `docker compose up`；客户端由服务端提供，自带 Python |
| 管理 | 每台电脑一个本机页面 | 服务端一个网页后台，中英双语 |

## 为什么

- **每台电脑各跑一整套，每台都有自己的问题。** 留下的大头是运行态，不是对话，本机硬盘越占
  越多。现在本机只留读取进度，对话交给 NAS；原始会话文件仍在各 agent 自己的位置。
- **记忆应该跨电脑。** 一台电脑一份记忆，换台电脑就又从头讲起。
- **按产品写适配跟不上。** 新 agent 出现得比适配写得快。现在由 agent 说清楚自己是谁、会话
  长什么样，时间图书馆只负责读懂这份描述，没有为任何产品写的代码。
- **记忆要能当凭据用。** 每条都指回原话，还要分清那句话是谁说的：一条只建立在别人贴进来的
  报告上的"偏好"，不是你的偏好。
- **模型是选择，不是定死的。** 历史导入、每晚提炼、深度归纳各选各的模型和备用；模型余额用完
  或连不上，会自己隔一阵再试，不丢进度。

## 没有带过来的

- 每台电脑上的本机页面、安装器和服务。它们留下的历史可以带过来（见[从旧版迁移](从旧版迁移.md)）。
- 按产品写的适配，以及跟着它们的工具发现。
- Hermes 的 skill 与经验升级环。Hermes 的对话照常收，和别的 agent 一样。

旧版本一直留在[版本发布页](https://github.com/strmforge/time-library/releases)和 `v2026.9.11` 标签里。
