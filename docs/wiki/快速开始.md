# 快速开始

## 1. 服务端

在 x86-64（Intel / AMD）芯片、能跑 Docker 的 NAS 或 Linux 机器上，找一块本地盘建个文件夹（不要放在网络共享上：里面是
SQLite 数据库）：

```bash
mkdir -p time-library && cd time-library
curl -fLO https://raw.githubusercontent.com/strmforge/time-library/main/deploy/nas/docker-compose.yml
docker compose up -d
```

打开 `http://<NAS 地址>:9850`，设置管理密码；在「模型」页添加一个模型来源（地址 + 协议 + key，
拉取模型列表，测通），或者打开自带的本机模型；再给「日常提炼」选一个模型。后台有中文和英文，
用语言按钮切换。

## 2. 接入 agent

在「设备」页点「生成接入口令」，把那句话发给要接入的那台电脑上的某个 agent。它会照服务端上的
`/client/install.md` 做：

1. 把客户端连同它自带的 Python 解压到 `~/.time-library-client`（一条 `curl | tar`；
   Windows 10 以上用自带的 `curl.exe` 和 `tar.exe`）；
2. 用令牌 `tl.py pair`（每台电脑一次）；
3. 描述自己的会话文件，用 `tl.py check` 在自己的文件上试到它说看着对了，再用
   `tl.py report-agent` 报上来，连同自己支持什么（MCP、skill、提问前钩子），见[接入 agent](接入agent.md)；
4. `tl.py service install`（每台电脑一次）：登录后自动在后台上传；
5. 接上自己有的：`time-library` MCP、skill、提问前钩子。

同一台电脑再接别的 agent，在「设备」页点「再接一个 agent」：同样的步骤，不用再配对。

## 3. 接下来

- 一聊天，几秒内「总览」就能看到新对话。
- 每天凌晨 02:00（NAS 的时间）把新对话提炼成记忆。「记忆」页能看到每条的原话、谁借过、评价如何。
- 装之前就有的历史可以用 `tl.py import` 导进来，先在「导入」页扣着，选好范围再开始。

## 升级

- 服务端：后台「总览」有新版时点「更新到 …」，不用拉镜像；新版起不来会自己退回。换了运行环境的
  版本会写明要拉一次新镜像，在同一个文件夹里 `docker compose pull && docker compose up -d`。
  它保存的一切都在 `data/` 里。
- 客户端会自己跟着服务端的版本升级。
